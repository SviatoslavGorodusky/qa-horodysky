# Git Cheatsheet: 20 реальних ситуацій у роботі QA

| № | Життєва ситуація на проєкті | Команда | Що реально станеться своїми словами |
| :---: | :--- | :--- | :--- |
| 1 | Почав зливати гілку фічі в main, вилізли страшні конфлікти, я запанікував і хочу повернути все, як було до злиття | `git merge --abort` | Процес злиття миттєво скасовується, файли з конфліктами повертаються до первинного стану до команди merge. |
| 2 | Хочу дізнатися, що колеги напушили у віддалений репозиторій, але боюся поламати свої незавершені локальні файли | `git fetch origin` | Git оновить інформацію про стан гілок на сервері, але не чіпатиме твій локальний робочий код. |
| 3 | Хочу отримати свіжі зміни з сервера і одразу влити їх у свою поточну гілку одним махом | `git pull` | Робить одночасно `fetch` (стягує зміни) та `merge` (вливає їх у поточну локальну гілку). |
| 4 | Хтось зламав локатор у файлі автотесту, треба дізнатися, який коміт і коли востаннє змінював конкретно цей файл | `git log -p -- path/to/file` | Покаже детальну історію комітів лише для цього файлу разом із рядками, які додавалися чи видалялися. |
| 5 | Написав автотест, зберіг, але він не працює і треба терміново скинути всі незбережені правки файлу до стану останнього коміту | `git restore path/to/file` | Скасує всі незакомічені зміни у зазначеному файлі, повернувши його стан із останнього робочого знімка. |
| 6 | Треба терміново перемкнутися на перевірку іншої гілки, але свій незакінчений код комітити ще зарано | `git stash` | Ховає всі поточні незакомічені зміни у тимчасову «кишеню», залишаючи робочу гілку повністю чистою. |
| 7 | Повернувся назад у свою робочу гілку і хочу дістати заховані недописані автотести з кишені | `git stash pop` | Дістає останні сховані зміни з кишені, повертає їх у файли та видаляє запис зі сховища stash. |
| 8 | Щойно зробив коміт, але помітив друкарську помилку в повідомленні або забув додати один дрібний файл | `git commit --amend -m "Нове повідомлення"` | Перезаписує останній коміт: додає нові файли зі staging або змінює його назву без створення зайвого коміту. |
| 9 | Додав файл у чергу індексу через `git add`, але зрозумів, що випадково захопив зайвий лог або скріншот | `git restore --staged path/to/file` | Прибирає файл зі staging (підготовки до коміту), але зберігає сам файл і зміни всередині нього на диску. |
| 10 | Потрібно створити нову гілку під задачу з Jira та одразу в неї перейти, не роблячи дві окремі команди | `git checkout -b feature/login-test` | Створює нову гілку від поточного місця і миттєво перемикає тебе на роботу всередині неї. |
| 11 | Треба швидко глянути коротку й зрозумілу історію проєкту у вигляді зручного графічного дерева гілок | `git log --oneline --graph --all` | Виводить компактний список усіх комітів у один рядок зі схематичними гілочками та стрілками злиття. |
| 12 | Не пам'ятаю, що взагалі накреслив у коді з моменту останнього коміту перед тим, як додавати у staging | `git diff` | Показує червоним та зеленим рядками різницю між поточними файлами на диску та останнім комітом. |
| 13 | Перевірив пул-реквест колеги, його гілка вже влита в main і більше не потрібна мені локально на ПК | `git branch -d feature/old-branch` | Безпечно видаляє локальну гілку (Git зупинить тебе, якщо там залишилися невзлиті зміни). |
| 14 | Випадково закомітив якусь нісенітницю локально і хочу повністю стерти останній коміт разом із файлами назавжди | `git reset --hard HEAD~1` | Безповоротно відкочує проєкт на один коміт назад, повністю знищуючи всі зміни цього коміту на диску. |
| 15 | Зробив неправильний коміт, але не хочу втрачати написаний код — треба скасувати збереження, лишивши код у редакторі | `git reset --soft HEAD~1` | Скасовує останній коміт, але повертає всі твої написані рядки у staging, готові до повторного виправлення. |
| 16 | Знайшов у чужій старій гілці один конкретний корисний коміт із фіксом локатора і хочу забрати собі лише його | `git cherry-pick <хеш_коміту>` | Копіює зміни зазначеного одного коміту та застосовує його поверх твоєї поточної гілки як новий коміт. |
| 17 | Команда випадково видалила або перезатерла потрібну гілку/коміт, здається, що все втрачено назавжди | `git reflog` | Відкриває чорний журнал абсолютно всіх рухів курсора Git (навіть стертих комітів), дозволяючи врятувати дані. |
| 18 | Тест зламався після створення нових тимчасових файлів запуску, треба одним махом вичистити все сміття з проєкту | `git clean -fd` | Примусово видаляє з папки проєкту всі нові невідстежувані файли та папки, яких немає під контролем Git. |
| 19 | Треба відправити нову створену гілку на GitHub, якої там ще ніколи не було | `git push -u origin branch-name` | Заливає гілку на віддалений сервер і пов'язує локальну гілку з хмарою для наступних швидких викликів `git push`. |
| 20 | Хочу перевірити, в якому стані робоча зона: які файли змінено, які додані в індекс, а які взагалі ігноруються | `git status` | Виводить повний звіт про поточну гілку, готові до коміту файли та невідстежувані зміни. |
