# Чек-лист тестування сутності «Кошик покупця» (Rozetka)

**Об'єкт тестування:** Модуль кошика та управління замовленнями перед чекаутом.  
**Мета:** Перевірка поведінки системи в усіх станах життєвого циклу за моделлю «Порожньо — Один — Багато — Гранично багато — Помилка — Немає прав».

## 1. Стан «Порожньо» (Empty State)
- [ ] **1.1. Відкриття порожнього кошика гостем:** Відкриття кошика неавторизованим користувачем. Очікується заглушка з ілюстрацією, напис «Кошик порожній» та активна кнопка «Перейти до покупок», що веде на головну сторінку.
- [ ] **1.2. Лічильник у шапці:** Перевірка бейджа кошика в глобальному хедері сайту. Очікується відсутність бейджа або числове значення `0`.

## 2. Стан «Один елемент» (Single Item State)
- [ ] **2.1. Додавання однієї позиції:** Додавання однієї одиниці товару з каталогу. Очікується відображення картки товару (назва, прев'ю, ціна за штуку, лічильник = 1), загальна сума дорівнює ціні товару, кнопка «Оформити замовлення» активна.
- [ ] **2.2. Зменшення кількості до 0 або видалення:** Зміна лічильника з 1 на 0 або клік по іконці кошика (видалити). Очікується миттєвий перехід у стан «Порожньо» без примусового перезавантаження сторінки.

## 3. Стан «Багато елементів» (Multiple Items State)
- [ ] **3.1. Групування за продавцями:** Додавання товарів від різних постачальників (наприклад, Rozetka та партнерські магазини). Очікується розділення замовлення на окремі пакети за продавцями та правильний загальний підсумок.
- [ ] **3.2. Застосування промокоду:** Введення дійсного купона/промокоду. Очікується перерахунок вартості замовлення з виділеним рядком відображення знижки.
- [ ] **3.3. Вибіркове видалення позиції:** Видалення одного товару з переліку з 3+ найменувань. Очікується видалення лише обраного рядка з автоматичним перерахунком суми для залишку товарів.

## 4. Стан «Гранично багато» (Boundary / Extreme Load)
- [ ] **4.1. Максимальна кількість одного товару:** Введення граничного значення лічильника (наприклад, 99 або 999 шт.). Очікується коректне форматування великих сум (пробіли розрядів тисяч), відсутність версткових налізань на сусідні кнопки.
- [ ] **4.2. Перевищення доступного залишку:** Введення значення, що перевищує наявність на складі (наприклад, введення 100 при залишку 5). Очікується автоматичне скидання до максимуму (5) та повідомлення «Доступна лише вказана кількість».
- [ ] **4.3. Велика кількість унікальних найменувань (50+ позицій):** Перевірка рендерингу довгого списку. Очікується плавний скролінг сторінки, відсутність зависання вкладки браузера та коректний підсумок вартості.

## 5. Стан «Помилка» (Error State)
- [ ] **5.1. Товар закінчився під час перегляду (Out of Stock):** Стан, коли позиція закінчилася на складі до кліку на оформлення. Очікується візуальне блокування картки (disabled), бейдж «Товар закінчився» та блокування кнопки переходу до оформлення до моменту видалення цієї позиції.
- [ ] **5.2. Невалідний або прострочений промокод:** Введення неіснуючого коду. Очікується підсвічування поля червоним, напис «Промокод недійсний», сума залишається незмінною.
- [ ] **5.3. Розрив з'єднання під час мутації даних:** Втрата мережі при зміні кількості. Очікується системне сповіщення про помилку зв'язку та повернення лічильника до попереднього збереженого значення.

## 6. Стан «Немає прав» (Forbidden / Access Rights)
- [ ] **6.1. Прямий доступ до чужого збереженого кошика:** Спроба відкрити URL кошика іншого користувача. Очікується статус 403 Forbidden або автоматичний редирект на власний кошик користувача.
- [ ] **6.2. Додавання товару з віковими/спеціальними обмеженнями гостем:** Додавання специфічної категорії без авторизації. Очікується вимога обов'язкового входу в акаунт перед додаванням або блокування переходу до чекауту.
